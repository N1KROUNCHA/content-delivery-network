🔑 Kyber-768 KEM

NIST PQC
Algorithm TypeLattice-based KEM
Security LevelNIST Level 3
Public Key Size1,184 bytes
Ciphertext Size1,088 bytes
Shared Secret256 bits → AES Key
ProviderBouncy Castle BCPQC

Used in Download Service: client sends ephemeral Kyber public key; server encapsulates the AES-256 key and returns ciphertext.

✍️ Dilithium3 DSA

NIST PQC
Algorithm TypeLattice-based Signature
Security LevelNIST Level 3
Public Key Size1,952 bytes
Signature Size3,293 bytes
HashSHA-256 of file bytes
ProviderBouncy Castle BCPQC

Used in Verification Service: signs SHA-256 hash on upload; Demo Client verifies signature after decryption.

🛡 AES-256-GCM

Symmetric
AlgorithmAES-256-GCM
Key Size256 bits (Kyber-derived)
IV / Nonce96 bits (random)
Auth Tag128 bits
PurposeFile payload encryption
ProviderJava Cryptography Extension

File bytes are encrypted with AES key derived from Kyber KEM. IV prepended to ciphertext for decryption on client side.

🔏 Signing Pipeline

Verification Service
1️⃣
SHA-256 Hash
Content Service computes SHA-256 of raw file bytes and sends Base64-encoded hash to Verification Service.
2️⃣
Dilithium3 Sign
Verification Service signs the hash using its Dilithium3 private key (Bouncy Castle BCPQC) and returns signature + public key.
3️⃣
Persist Metadata
Content Service stores file ID, hash, signature, public key, and upload timestamp in the H2 database.
4️⃣
Audit Log
Both Content Service and Verification Service emit structured audit events to the Logging Service.
